# 设计原则与决策规则

状态：`draft`。以下是起始规则，需要在真实页面中验证，而不是对所有产品强制同一布局。

## 信息先于装饰

先写出页面的主要任务、关键数据与下一步操作。每页有一个明确的主标题；同一操作区域通常只设一个主要按钮，其余用次级或文字操作。

分组优先使用留白、对齐和标题。只有内容具有独立意义、状态或操作边界时才使用卡片，不把所有文本包装进卡片。不要加入无业务意义的统计数字、图表、渐变或插图。

## 层级与节奏

- 从预设选择标题、正文、辅助说明三级排版，使用字号、字重和间距形成层级。
- 以 4px 为基础间距尺度；同级分组保持一致，分组间距大于组内间距。
- 全页使用一套语义配色。强调色用于主要行动、选中与焦点；状态色同时配文字或图标，不仅靠颜色表达。
- 圆角区分控件与容器；阴影只表达浮层或层级，不给每个区块附加阴影。

## 布局选择

| 内容特征 | 优先布局 | 应避免 |
| --- | --- | --- |
| 多模块、频繁切换 | 侧边导航 + 页头 + 内容区 | 仅为后台外观增加无用侧栏 |
| 文章、个人介绍、文档正文 | 阅读宽度受控的内容列 | 为填满宽屏拉长每行文字 |
| 搜索、筛选、批量操作、表格 | 筛选与操作靠近结果列表 | 筛选状态隐藏在与结果无关的位置 |
| 产品价值和转化 | 价值说明 + 真实证据 + 行动路径 | 虚构客户、评价、增长数据 |

宽度和断点是本库默认值。优先采用项目现有约束，以内容开始拥挤的位置决定实际切换点，不根据设备品牌判断布局。

## 密度与设备

舒适密度适合设置与轻量工作台；紧凑密度适合数据密集任务，不能通过缩小正文或隐藏标签获得。桌面紧凑控件可采用 32px，触屏主要控件建议 44px；这是本库体验目标，不把它表述为 WCAG 的统一硬性尺寸。

在 375、768、1440px 宽度验证典型布局，必要时增加项目指定尺寸。移动端导航转为可关闭抽屉；表格优先保留关键列并提供可访问的局部横向滚动或详情入口，不截断关键操作。200% 缩放后仍应能阅读和操作。

## 状态与交互

每个有数据或提交行为的界面说明加载、空数据、错误、成功与禁用状态。区分首次无数据与筛选无结果；错误给出恢复路径，保留用户已输入内容；成功让用户知道操作结果。禁用有明确原因，且原因不只通过悬浮提示提供。

本地与远程筛选、分页、排序、URL 状态同步、提交和取消均需在 Brief 中说清楚。真正的业务失败从真实数据状态产生；演示用状态开关只进入工作台，不混入产品流程。

## 基本无障碍

使用语义化元素，所有输入具有可关联标签，焦点始终可见。对话框开启后管理焦点，关闭后返回触发元素；支持键盘退出和完整操作。优先复用已实现这些行为的成熟组件。

普通文本与背景的对比度以 4.5:1 为最低目标，符合定义的大字号文本为 3:1；不以低透明度辅助文字牺牲可读性。[WCAG 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

WCAG 2.2 的目标尺寸最低标准为 24×24 CSS px，并包含间距、内联等例外；项目应按实际控件判断，44px 是本库触屏设计建议。[WCAG 目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)

尊重减少动态效果设置。图表提供摘要或数据表，不把颜色或悬浮提示作为唯一信息入口。自动检查只能辅助，不能替代实际键盘和页面验收。
