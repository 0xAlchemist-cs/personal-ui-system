# Phase 03 — 独立项目复用试点计划（Conditional）

> 状态：**候选执行计划，未启动**。依赖 Phase 02 Gate 通过。总纲：`../MASTER-PLAN.md`。不能把此文件作为实施成功的证明。

## 0. 目标、范围和唯一引用

目标：证明一个独立消费者可以从**已验证的** Personal UI System 资产中取得一份固定版本、引用闭合的快照，并在不依赖知识库所在本机目录的情况下独立检出、安装、构建和运行。

- 既有事实源：`docs/project-reuse.md`（快照原则）、`docs/asset-lifecycle.md`（成熟度）、`design-system/tokens/README.md`（Token 契约）、Phase 02 的真实实现与证据、所选消费者项目的 `AGENTS.md`/lockfile。
- 不重新写 `UI Brief`、Token 值或 UI 组件需求；不在本阶段建立公共 npm 包、Registry 或统一跨框架运行时。
- 本计划按**验证一条真实消费路径**设计，不宣称已支持全部五种 UI 框架。

## 1. 前置 Gate

- [ ] Phase 02 已交付可用页面、Storybook 和正式验收记录；确认哪些资产已 `validated`。
- [ ] 选定一个独立消费者项目与其固定提交，明确其技术栈、权限和非生产试点边界。
- [ ] 选择需复制的资产清单，固定本库来源 SHA；不得靠“最新版本”隐式漂移。

## 2. Task 1 — 确定消费者与最小复用范围

- [ ] 记录消费者项目/路径、技术栈、现有 UI 体系、要复用的具体预设、Token 和设计规范。
- [ ] 检查消费者已有设计规则；若冲突，以实际消费者约束为先，明确覆盖，不强行迁移组件库。
- [ ] 明确验收页面或测试场景，确保能客观判断主题和设计规则是否生效。

**完成证据：** 一份包含消费者提交 SHA、复用清单与明确冲突的记录。

## 3. Task 2 — 建立闭合快照契约

- [ ] 基于 `docs/project-reuse.md` 为消费者创建 `.personal-ui/` 目录，保留所有被引用的文件及依赖；不能只复制 `SKILL.md`。
- [ ] 提供 `manifest.json`，至少记录 `sourceRepository`、`sourceCommit`、`systemVersion`、`preset`、`copiedAt`、`includedFiles`、`localOverrides`。如写校验器，需要覆盖文件存在性及相对引用闭合。
- [ ] 消费者 `AGENTS.md` 只引用本项目内路径；规范链接和资产路径在项目独立检出时应保持有效。

**完成证据：** manifest 与实际快照一致，本地相对引用检查通过。

## 4. Task 3 — 完成一次真实消费与独立构建

- [ ] 以消费者真实版本解析主题；不能直接将自定义 JSON 盲传给第三方 Provider。
- [ ] 运行一个可观测的 UI 场景，确保消费的变量确实影响实际渲染（例如按钮/容器/间距）。
- [ ] 从干净目录独立检出消费者，按锁文件安装与构建；主动排查磁盘绝对路径、跨仓库源码引用、软链接与隐式依赖。
- [ ] 如果消费者技术栈与 Showcase 不同，只检验可迁移的规范和 Token；**不得宣称 React 组件跨框架可直接复用**。

**完成证据：** 独立构建日志 + 页面或 Story 验证记录 + 路径依赖扫描结果。

## 5. Task 4 — 收口与演进决策

- [ ] 记录资产来源 SHA、变更、局部覆盖、视觉差异、实际复用收益与剩余手动步骤。
- [ ] 对重复使用的部分评估是否需要轻量复制脚本；**只有真实痛点出现后**才建立 CLI/包发布计划。
- [ ] 更新 `docs/roadmap.md` 与 `CHANGELOG.md`，只写已执行结论；保留消费者版本钉住及后续升级步骤。

**Gate 03：** 至少一个独立消费者从干净检出成功安装与构建，展示设计资产实际生效；完整引用、无本机绝对路径；验证记录真实可复现。否则继续留在 Phase 03。

## 6. 每个任务的小 Prompt（按顺序单独使用）

### P03-T1｜消费者选型
> 请执行本文件 **Task 1**。先确认 Phase 02 Gate 有可核验的证据；只做消费者现状调查和复用范围记录，不改 UI 实现。读 `docs/project-reuse.md` 与所选消费者的实际 lockfile/AGENTS。输出消费者版本、复用范围、冲突及 Task 1 验收证据。未指定消费者时，以可隔离的测试消费场景形成候选方案，但不得声称试点完成。

### P03-T2｜快照打包
> 请执行本文件 **Task 2**。基于 Task 1 的已确认资产清单形成 `.personal-ui/` 闭合快照与 manifest；检查所有链接、引用和版本。只在消费者仓库内保存相对路径，不写跨仓库绝对导入。提供 manifest 校验结果和新增文件清单，不实现包管理器或 Registry。

### P03-T3｜独立验证
> 请执行本文件 **Task 3**。从干净目录独立检出消费者并按锁文件安装、构建和运行，证明选定预设实际生效；核查不存在本机路径或隐式引用。必须报告原始命令、运行环境、失败与修复、截图或页面证据。若缺权限或环境无法运行，标记未验证，不能通过 Gate 03。

### P03-T4｜收口
> 请执行本文件 **Task 4**。核对 Task 1～3 的验收证据和 Gate 03，评估实际复用收益与仍然需要手动操作的步骤。更新唯一事实源中的路线图、变更记录和来源记录。除非已经出现明确重复安装痛点，不创建公共包、Registry 或自建 MCP。输出是否允许进入 Phase 04 的结论。
