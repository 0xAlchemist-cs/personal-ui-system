# 独立项目复用策略

本文件定义独立项目的集成边界；当前没有通用安装器或组件包，本库 `personal-ui` Skill 尚未全局注册。已安装的第三方官方 Skill 另见 [工具接入记录](ui-tooling.md)。

[P03-T2 消费者快照](../records/2026-10-24-p03-t2-snapshot.md) 已提供一次固定版本、引用闭合的实际示例及静态校验器；这是试点内的文件约定，不是通用安装器。消费者根 AGENTS 引用自己的快照 Skill；静态检查通过不等于独立安装、构建或页面验收通过。

[P03-T4 收口](../records/2026-10-24-p03-t4-closeout.md) 已核对 Gate 03：一个独立 React/Ant Design 消费者从完整归档全新检出、安装、构建和运行，实际验证所选预设。固定来源 `16184844550f970570408a79e649a37dd7fe5c0d`、消费者验收提交 `a349428854e7cf203ee29d0211ef8a7572bdff10`；仅覆盖报告中的场景与环境，不是其他框架的兼容保证。

## 先复制知识，后分发稳定代码

独立项目保存自己的设计快照，例如 `.personal-ui/`。把所选风格、它引用的基础 Token、总控规范和相关模式复制进去，记录库版本、来源仓库及提交号（如果已有）、复制日期和本地修改。

目标项目的 AGENTS.md 引用自己的相对路径，例如 `.personal-ui/prompts/frontend-development.md`。不要引用本库所在磁盘路径，不建立跨仓库目录链接，不从本机源码目录导入组件。

## 保证引用闭合

复制前检查被选文件的全部本地链接和数据引用。若保留原相对目录结构，必须同时复制这些依赖；若裁剪文件，则同步改写指向未复制内容的链接。不要把仅复制一个 SKILL.md 描述成完整安装。

本库的 `skills/personal-ui/SKILL.md` 是仓库内入口，通过相对路径读取本库资产。脱离本库单独安装前，应将所需资产作为 Skill 自带资源一同打包，并调整内部引用；具体接入机制在阶段 03 按宿主规则验证。

## 来源记录示例

```json
{
  "system": "personal-ui-system",
  "version": "0.1.0",
  "source": "https://github.com/0xAlchemist-cs/personal-ui-system",
  "copiedAt": "2026-10-22",
  "preset": "minimal-saas",
  "localChanges": []
}
```

该记录只作概念说明，不授予资产成熟度，也不替代依赖锁文件。试点实际的字段、源/目标路径、局部覆盖与哈希以 [manifest 审计副本](../../tests/manual/consumer-pilot/t3-manifest.json) 和 T2 契约为准，不将示例当成另一套安装标准。

## 快照升级与回退

1. 在消费者自身分支固定最后验收提交、manifest 和依赖锁，保存可恢复版本。先确认工作区状态，不覆盖未提交修改。
2. 选定完整目标来源 SHA，比较所用文件、Token 语义、资产成熟度和实际框架/依赖兼容性。没有明确升级需求时保留原快照，不跟随知识库 HEAD 自动漂移。
3. 在消费者内合并目标文件，逐项保留或重做已有 `localOverrides` 与导入重定位；冲突按消费者明确约束处理。保留许可，更新来源版本/日期、Git Blob、源/目标 SHA-256、实际清单与根集成哈希，检查全部本地引用；不要整目录盲目覆盖。
4. 使用消费者自己的锁文件从干净检出安装，运行适用的快照、类型、Lint、测试和构建，并启动页面核对典型状态、键盘、响应式与主题差异。宿主全局路径与跨库链接不能补齐依赖；维护者审阅结果后才采纳新提交。
5. 升级失败时保留失败记录，回到最后已验收的消费者版本重新验证，或在新目录从其 Git 归档恢复。共享历史优先通过可审阅提交撤销升级，不用强推或强制覆盖工作区；恢复旧 manifest 和锁文件应与该版本源码一致。

本流程已在 T4 文档化，尚未实际演练一次来源升级/回退，不代表存在自动迁移器。消费者目前没有独立远端；源码更改需要自身 Git 提交及适当备份。现有 [消费者 bundle](../../tests/manual/consumer-pilot/t3-consumer-validated.bundle) 可恢复 T3 已验收版本，不能替代每次变更后的验证和备份。

## 稳定后的分发

当组件经过真实项目验证并出现重复需求时，再选择独立包、私有 npm 或 Registry。消费者固定版本，并在自身 CI 中安装和构建。分发能力不应要求部署环境访问个人电脑，也不需要先开发自定义 MCP Server。
