## Global Constraints

- [需求基线](2026-11-01-ui-studio/requirements.md) 为本次产品范围；[数据契约](2026-11-01-ui-studio/contracts.md) 为模块接口唯一来源。
- 本轮交付大纲、模块计划和独立提示词；不安装编辑器、不改应用入口、不修改旧 Brief/Token 或消费者。
- 真实代码生成效果图；动态组件必须有实际可操作预览。参考图片不能伪装成已实现组件。
- 不接 AI、不要求 API Key、不新增账户、后台服务或云同步。
- 三方案采用同一组件需求、页面划分及风格，必须有可解释的结构差异；不承诺无限原创设计。
- 保留现有三套预设及成熟度。工作台中的用户样式覆盖只存项目文档，不改公共 Token 或冒充符合 UI Brief 1.0 的新预设。
- 先复用官方组件和现有实现；外部数据在导入边界校验一次，内部使用类型。单次逻辑不提前抽象，极低概率防护按项目偏好处理。
- m3e-canvas 的固定源码、许可、已知耦合与候选比较见 [来源与选型](2026-11-01-ui-studio/sources.md)。
- 本计划的执行提示词按用户明确要求单独成文件，覆盖旧总纲“微型 Prompt 留在计划末尾”的默认建议；每份只引用对应规格，不复制第二套需求。

## 用户路径

打开 UI system → 图库筛选/真实预览 → 加入购物车 → 确认页面分组 → 看三套多页面方案。
喜欢一套 → 克隆为可编辑稿；都不喜欢 → 保留购物车进入自由拼装。
编辑/真实预览切换 → 调整桌面并检查平板手机 → 保存 → 复制提示词或下载参考包。
默认导出最终编辑稿；用户可明确选择导出三套候选及对应编辑稿。候选原稿与编辑稿不互相覆盖。

## 推进与停止条件

1. **先证明能编辑真实组件。** M00 用四类组件证明多风格、交互、编辑回写与移动适配；不合格时停止后续实施并提交替代路线，不能只嵌入外部网站充当完成。
2. **建立数据到预览的通路。** M01～M03 的交付可独立审查：文档往返不丢数据、图库可看可选、分组可确认。
3. **实现核心产品差异。** M04 与 M05 分别验收“三个不同设计”及“都不喜欢仍可拼装”。M05 不能因生成器未完成而失去独立拼装入口。
4. **闭合交付。** M06、M07、M08 分别保证输出一致、浏览器保存可恢复、桌面快捷方式进入新首页。
5. 适用的机器/人工验收遵循 [唯一验收约定](../../../tests/README.md)；新功能的具体旅程见 [验收矩阵](2026-11-01-ui-studio/acceptance.md)。没有执行证据不能勾选完成。
6. 不重写 Phase 02～04 历史计划或验收结论。旧成员页和 17 个 Story 保留可达。
