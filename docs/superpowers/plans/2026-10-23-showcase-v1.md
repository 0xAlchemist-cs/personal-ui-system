# Personal UI System 首个可视化工作台实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将现有 `minimal-saas` 规则落实为一张可操作的成员管理示范页，并用 Storybook 展示其组成与主要状态，完成首次真实页面验收。

**Architecture:** 在 `showcase/app/` 建立独立演示应用；复用仓库现有 Brief、Token、模式与官方组件。页面和 Stories 共用业务组件及主题适配，不提前建立公共组件包。

**Tech Stack:** 建议 React + TypeScript + Vite + Ant Design，搭配 Storybook 的 React/Vite 集成；单元测试使用 Vitest。这是首个工作台的选型建议，其他项目继续按各自技术栈选型。

状态：**计划草案，尚未实施**。编写日期：2026-10-23。本文记录下一阶段任务，不表示已存在应用、启动命令或验证结果。

- 先复用 Ant Design 官方组件；只为明确的页面职责组合组件，不包装一套同名 Button、Table 或 Form。
- 演示数据仅存于页面内存；不接入账号、权限、真实接口、登录或持久化服务。
- 当前任务只交付计划；执行本计划时才初始化应用、安装依赖并核对版本。不得把已安装 Skill 当作运行时依赖或 MCP。

## 为什么先做这一版

第一阶段已经具备三套候选风格、Token、页面规格、UI Brief、开发规范，以及五套组件体系的知识接入。当前缺少的证据是：这些规则组合后，页面是否好用、视觉是否一致、代码能否复用。

因此，下一步交付一张完整页面和必要的组件预览。页面负责验证整体体验，Storybook 负责检查局部状态。首版通过验收后，再决定下一张页面与第二套风格。

| 阶段 | 当前情况 | 本计划的关系 |
| --- | --- | --- |
| 01 设计知识库 | 基础已建立，风格尚待真实页面验证 | 直接复用，按页面证据修正 |
| 02 组件工作台 | 尚未实现 | 本计划交付首个可运行版本 |
| 03 独立项目集成 | 官方 Skill 已接入，跨项目试点未完成 | 首版完成后再选一个独立项目试用 |
| 04 自动验证与分发 | 尚未实现 | 后续按需要增加视觉回归和资产分发 |

## 任务 2：建立最小应用与主题通路

**修改范围：** `showcase/app/` 的配置、入口与 `src/theme/`。

- [ ] 通过对应官方文档核对 Node、React、Vite、Ant Design、Storybook 和 Vitest 的兼容版本，再安装并生成锁文件。记录实际 Node/npm 版本与核验日期，不把 Ant Design CLI 版本当作组件依赖版本。
- [ ] 使用 Vite React/TypeScript 脚手架建立 `showcase/app/`；保留现有 `showcase/README.md`，不用根目录工作区管理或发布配置。
- [ ] 定义 `dev`、`storybook`、`typecheck`、`lint`、`build`、`build-storybook`、`test` 脚本；`test` 使用非监听运行模式，`typecheck` 覆盖应用、Stories 和受 TypeScript 管理的配置。
- [ ] 实现 `resolveTokens(primitives, semantic, overrides): Record<string, string>`，三个参数分别取原始值 JSON、语义 JSON、风格 JSON 的 `tokens` 字典，第三项用于覆盖。先检查两层键无冲突、覆盖键属于语义层，再递归解析完整别名；未知引用、循环引用和原始值引用语义层均报明确错误。
- [ ] 测试至少覆盖：`color.accent` 最终为 `#2563eb`；预设覆盖优先；未知引用、循环引用、非法覆盖被拒绝；不能改变原始输入。
- [ ] 将已解析语义值交给类型明确的 Ant Design `ThemeConfig`。颜色/字体保留字符串；`fontSize`、`borderRadius`、`controlHeight` 由对应 `px` 值转数字；`lineHeight` 由数字字符串转数字，非法单位或非有限值立即报错。
- [ ] 对 `minimal-saas` 验证 `colorPrimary = #2563eb`、`borderRadius = 8`、`controlHeight = 40`；对单位转换的非法输入补充适配测试。
- [ ] 页面通过 `ConfigProvider` 与 Ant Design `App` 上下文应用主题、中文文案与反馈；Stories 复用同一 Provider。使用上下文内的消息/对话框 API，避免静态反馈脱离主题。
- [ ] 布局使用语义 CSS 变量：`--pui-color-canvas`、`--pui-space-page` 等；断点遵守现有 768/1024px 规则。媒体查询使用构建时确定的值或读取 Token 的 `matchMedia`，不在 CSS 媒体条件中直接使用 `var()`。
- [ ] 应用和 Storybook 读取同仓库设计 JSON 时，按配置文件位置推导路径；若需放开 Vite 文件访问，仅配置所需设计资产目录，不写机器绝对路径。

**完成条件：** 最小页面与 Storybook 均能加载同一主题；单元测试、类型检查、Lint 与两种构建通过。

## 任务 3：完成成员管理交互

**修改范围：** `src/components/`、`src/features/members/`、`src/App.tsx`。

- [ ] 定义 `Member`：`id/name/email/createdAt` 为字符串，`status` 为 `active | disabled`；查询状态包括关键词、状态、日期排序与页码。视图数据由原始记录和查询计算，不重复存储筛选结果。
- [ ] 实现纯函数 `queryMembers(members, query)`，返回 `rows/total/page`：姓名或邮箱不区分大小写包含匹配，与状态条件同时生效，排序后按 10 条分页，空结果页码为 1，越界页码收敛到有效值。
- [ ] 使用固定小样本测试组合筛选、日期升降序、分页边界、不修改输入，以及编辑使末页记录退出筛选后页码正确收敛。关键词、状态或排序变化时由页面将页码重置为 1。
- [ ] `AppShell` 负责导航、抽屉与内容布局；`ContentPanel` 只承接本页筛选和表格分组需要的标题、内容与间距。官方输入框、按钮、表格、分页、表单和对话框直接复用。
- [ ] `MemberFilters` 传出查询变更；`MemberTable` 传出分页、排序、编辑事件；`MembersPage` 维护唯一成员集合和查询状态；不引入全局状态库。
- [ ] `EditMemberDialog` 编辑姓名和邮箱；非空姓名、合法邮箱才能保存，校验错误关联字段并保留输入，取消不更新记录。保存更新内存并明确提示“刷新后恢复”。
- [ ] 键盘可进入抽屉和对话框、按 Escape 退出、在正确范围内移动焦点；关闭回到触发按钮，若编辑后该行已离开筛选结果，回到仍存在的表格标题或筛选入口。
- [ ] 正文明确演示数据边界；`disabled` 成员以文字状态展示，仍可编辑其基本信息。不添加没有行为的导航、统计数字、导出或新增按钮。

**完成条件：** 搜索、筛选、排序、分页、保存、取消可以组合使用，语义和焦点行为与 Brief 一致。

## 任务 4：补齐 Storybook 与适用状态

**修改范围：** `.storybook/` 与计划中的 `*.stories.tsx`。

- [ ] `AppShell` 展示宽屏导航与小屏抽屉；`ContentPanel` 展示信息分组与标题层级；成员相关 Stories 覆盖表格、表单和完整页面布局。
- [ ] 使用固定数据和同一个主题，不在 Stories 内另写一套产品交互。需要状态输入时仅开放有用的参数，演示控制留在 Storybook。
- [ ] 在 Story 文档说明用途、输入、事件、依赖、预设、密度及已验收范围；不把 Ant Design 官方全部组件重新录入一遍。
- [ ] 逐项落实下表，确保每个状态能实际预览与操作。

| 状态 | 验证方式 |
| --- | --- |
| 默认 | 30 条记录，日期降序，分页与状态文案明确 |
| 加载 | 仅 Story 模拟表格加载，不给静态演示页加入人工延时 |
| 无初始数据 | Story 使用空集合，说明暂无成员 |
| 筛选无结果 | 页面组合筛选可触发，保留输入并提供清除筛选 |
| 错误 | 对话框无效字段有就地提示，输入不丢失；无虚构网络错误 |
| 成功 | 保存后更新页面内存，提示演示成功及刷新恢复边界 |
| 禁用 | 无效表单的保存按钮禁用，有可读原因，键盘可到达错误信息 |
| 焦点 | 搜索、筛选、表格操作、分页、抽屉、对话框均有可见焦点 |

**完成条件：** Stories 可搜索、可操作，状态覆盖不依赖修改源码；应用构建和 Storybook 静态构建均通过。
