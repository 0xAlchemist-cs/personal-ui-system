## 模块出口

| 模块 | 必须提供的可复核结果 | 不算通过的情况 |
| --- | --- | --- |
| M00 | 真实组件接入、双风格、编辑/运行分离、手机修正、序列化往返证据 | 只有源代码阅读、上游网页嵌入或图片近似 |
| M01 | 文档往返、非法引用拒绝、命令/撤销和设备覆盖行为测试 | 仅 TypeScript 编译成功 |
| M02 | 36 个公开条目的真实封面/详情、交互和三风格检查 | 颜色变体凑数、动态图仅用截图 |
| M03 | 可选可删的车、分组修正、冲突处理和确认门槛 | 无法修改的“智能建议”或不明归属直接丢弃 |
| M04 | 三种结构、确定性、去重、有限组合不足说明 | 三张同结构换颜色、随机摆放或组件缺失 |
| M05 | 候选编辑与空白拼装两入口；样式/层级/设备覆盖/撤销真实回写 | 只改 DOM、不入文档，或修改手机同时破坏桌面 |
| M06 | 文本/图片/JSON 同一修订，final/all 选择符合契约 | 旧提示词配新图片、漏图仍提示完整成功 |
| M07 | 真浏览器关闭重开恢复、导入新 ID、失败可备份 | 仅内存 mock、无提示地用空数据覆盖 |
| M08 | 新首页与完整旅程、旧功能回归、实际 CI 与人工证据 | 仍从成员表单开场，或把旧检查数量当新结果 |

## 固定验证材料

- Fixture A：SiteHeader、Hero、FeatureGrid、PricingSection、SiteFooter，场景官网。
- Fixture B：SidebarNavigation、SearchFilters、StatsOverview、DataTable、PaginationBar，场景后台。
- Fixture C：只有 Button，验证方案数不足时的真实说明。
- Fixture D：Hero、ArticleList、DataTable、LoginForm，加一个待分配 Button，验证多页面分组。
- Fixture E：Switch、Tabs、EditDialog、Progress，验证运行态与设计态分离。
- 每个场景使用固定演示文本、日期、数据和图片。不得生成虚构商业成绩、客户案例或授权内容来装饰验收。
- 页面布局在实际 1440×900、768×1024、375×812 视口检查；画布缩放是辅助工具，不代替真实 viewport。风格检查覆盖三套预设，但成熟度仍按已有记录。

## 两条完整旅程

### J1 选择喜欢的方案再编辑

1. 从无 hash 的首页打开图库，按后台场景找到 Fixture B 的五项并加入购物车。
2. 确认归属到一个管理页面，生成三方案；比较结构差异与所选组件是否完整。
3. 选择第二套，进入工作稿，将标题改为“团队成员”；修改间距和一个按钮颜色。
4. 切换到手机，调整某区域顺序或宽度，回桌面确认该设备覆盖未污染基础布局。
5. 进入运行预览，执行筛选/表格或对话框的实际交互；返回编辑，确认预览状态未写入历史。
6. 填写用途“团队管理员检索成员并编辑姓名和邮箱”，保存，刷新并重开项目；复制最终提示词，下载 final 参考包；核对用途、文字、样式、组件清单、图片和 revision。
7. 选择 all，确认第二套为编辑稿，其他两套仍为原稿，三套页面集合相同。

### J2 全部不喜欢，进入自由拼装

1. 使用 Fixture D 确认多个页面，生成候选后点“都不喜欢，自己拼装”。
2. 验证页面结构为空容器、所选条目仍在插入区；没有自动套用任何不喜欢的方案。
3. 插入 Hero、文字/按钮、列表，切换到另一页插入表格；拖动、缩放、修改字体和背景。
4. 在自由容器重叠两个组件，调层级；在手机预览发现越界提示并独立调整。
5. 通过撤销重做验证恢复；运行一次真实动态组件。
6. 保存并下载项目 JSON；导入为新项目，确认不覆盖原项目，预览与编辑属性一致。
7. 导出 final 成功；不适用的 all 选项给出解释，而不是偷偷返回三个复制品。

## 典型状态与失败恢复

| 场景 | 预期行为 |
| --- | --- |
| 图库无筛选结果 | 展示当前条件，提供清除操作 |
| 组件封面失败 | 标记封面不可用，可转真实详情；不换概念图 |
| 空车/待分配/导航冲突 | 自动生成按钮不可用并显示明确原因，可回图库/修正归属 |
| 生成有效组合少于三种 | 显示真实数量及限制，自由拼装仍可进入 |
| 没有工作稿 | final 导出不可用，明确引导选择候选或创建工作稿 |
| 复制被浏览器拒绝 | 显示可全选文本并说明手动复制方法 |
| 导入损坏/版本不支持/未知组件 | 显示字段与问题，当前项目保持不变 |
| 浏览器存储失败 | 显示未保存；内存稿、复制和文件导出仍可用 |
| 单页截图或字体图片加载失败 | 指明页名和重试，不交付伪完整 ZIP |
| 自由定位手机裁切 | 可定位到问题节点，有单设备调整和重置入口 |
| 成功保存/复制/导出 | 完成实际操作后才反馈，不提前显示成功 |
| 动效减弱设置 | 仍能理解状态变化，预览提供可用的减弱效果 |

## 计划中的最小行为测试示例

M01 在 document/project.test.ts 中至少包含这类往返用例；这段是待实现测试规格，不是本轮运行结果：

```ts
import { expect, it } from 'vitest';
import { createProject, parseProject } from './project';

it('round-trips a new project without losing fields', () => {
  const project = createProject('Roundtrip');
  expect(parseProject(JSON.parse(JSON.stringify(project)), [])).toEqual(project);
});
```

M04 测试至少断言有效 Fixture A 的候选 signature 唯一、数量为三、同 seed 输出相同、组件归属覆盖完整。M05 的浏览器断言必须读取保存后的文档和真实预览结果，不能仅断言“点击按钮被调用”。M06 解压 ZIP 对照 manifest、PNG 和 project.json 的修订及页面，不能只断言下载链接存在。

## 机器检查与人工证据

在本仓库根目录（Windows 可用 npm.cmd）：

```sh
npm run check --prefix tools/quality
npm test --prefix tools/quality
npm --prefix showcase/app run typecheck
npm --prefix showcase/app run lint
npm --prefix showcase/app run test
npm --prefix showcase/app run build
npm --prefix showcase/app run build-storybook
npm --prefix showcase/app run test:e2e
```

依赖安装按各自锁文件执行；浏览器首次安装与固定 Chromium 使用应用 README 的命令。只在 UI 实施后运行适用浏览器旅程，计划文档本身无需新增应用测试。新增测试有意义时覆盖失败和恢复，不为可逆文案添加镜像测试。

人工检查图库信息层级、36 项效果与用途、三方案是否值得比较、动态预览、纯键盘、实际 200% 缩放、三视口及编辑手势。画布主编辑器支持桌面浏览器；窄屏保留图库/预览，并显式说明编辑限制，不能截断按钮使操作无处可用。

每模块报告包含：受检 SHA、依赖与 OS/浏览器/字体/语言/时区/viewport、实际命令及退出码、通过/失败/未执行/不适用、截图及交互步骤、剩余问题。图像仅是诊断/人工验收材料，不创建自动像素基线。CI 需核对实际待交付 SHA 的两个 job，不用旧 SHA 成功代替。
